## Closed out: the 3 PlantUML syntax errors flagged above

Fixed for real, verified via direct `docker run plantuml/plantuml`
invocations against minimal repros (not guessed) — all three turned out
to be genuine PlantUML syntax rules, not the `--`-in-text theory the
flagging pass first suspected (removing `--` alone did not fix any of
the three; each needed its own real fix, found by bisecting a minimal
reproduction down from the full file):

- **`docs/patterns/bitemporal-modeling.md`**: a floating one-line
  `note top: ...` inside a `concise` (timing) diagram is invalid —
  `note` in a timing diagram must attach to a declared lifeline. Fixed
  to `note top of TT: ...`.
- **`docs/patterns/watermarks-event-time-ordering.md`**: the same rule,
  same fix, in a `robust` timing diagram — floating `note bottom` →
  `note bottom of ET`.
- **`docs/patterns/safe-method-with-request-body.md`**: two independent
  bugs stacked in one diagram. First, `rectangle` does not support the
  `Element : field` class-body syntax at all (confirmed: `object` does);
  changed `rectangle "GET" <<Method>> as GET` to `object "GET" as GET
  <<Method>>`. Second — the real reason the `object` conversion alone
  still failed — **a `<<stereotype>>` placed before `as alias` on a
  quoted-name declaration is itself invalid PlantUML syntax**; it must
  come after the alias (`"X" as X <<Stereotype>>`, never `"X"
  <<Stereotype>> as X`). This second bug would have broken the
  `rectangle` form too, independently of the first. `skinparam
  rectangle { BackgroundColor<<Method>> ... }` was also updated to
  `skinparam object { ... }` to match the element type actually used.

All 397 repo diagrams now extract and render clean in one pass
(`node scripts/extract-diagrams.mjs && node scripts/render-diagrams.mjs`,
`Done.`, no errors) — the full backlog this session's Phase 0 pattern
docs left behind is now closed, not just flagged.
