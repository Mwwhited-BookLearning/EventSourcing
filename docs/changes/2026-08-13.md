# Changes — 2026-08-13

## `@guidepup/virtual-screen-reader` added to narrow (not close) the manual screen-reader-pass gap

`TODO.md`'s own long-tracked gap — `ADR-073`/build-plan item 45's exit
criterion asks for "a manual screen-reader pass (a real NVDA/JAWS/
VoiceOver session)" confirming `GenericFallbackView` is fully navigable,
and no such software is installable/operable in this environment — got a
real, verified narrowing rather than staying purely a documented
limitation. Direct user request, following up on a question about
whether any emulator exists for this: `@guidepup/virtual-screen-reader`
does, confirmed via its own npm/GitHub pages (fetched directly, not
assumed) — a pure JS/TS accessibility-tree simulator with no OS-level
screen-reader engine dependency at all, so it genuinely runs here where
NVDA/JAWS/VoiceOver themselves cannot.

Added to `client-web/packages/reference-app` as a devDependency
(`^0.32.1`, latest at the time). `a11y.virtualScreenReader.spec.ts` (new,
5 tests) mounts the same components `a11y.spec.ts`'s own `axe-core`
suite already covers, walks the simulator's full accessibility tree over
the real rendered DOM (`attachTo: document.body`, matching that file's
own convention), and asserts on the actual ordered phrase log rather
than reasoning about markup by hand:

- `GenericFallbackView`'s table genuinely announces `"row, carrier UPS"`
  with `"rowheader, carrier"` ahead of `"cell, UPS"` in the same row —
  the exact claim the pre-existing `<th scope="row">` fix made (found
  and fixed in an earlier pass by reasoning about screen-reader behavior
  directly, never previously proven this concretely) confirmed, not
  merely argued.
- An Extensions-sourced property's visual `"(Extensions)"` marker
  actually reaches the tree (`"emphasis" ... "(Extensions)"`), not just
  styled visually.
- The `Retry sync` button is reachable with a real accessible name
  (`"button, Retry sync"`).
- A `ViewDefinition`-template `<dl>` pairs its `term`/`definition` roles
  in navigation order (`"term" ... "Carrier" ... "definition" ... "UPS"`).

**A real limit found while writing these, not glossed over**: this
tool's own README states it "should not be used as a substitute for
testing with real screen readers and with real screen reader users."
Confirmed directly rather than just quoted: `FlagRow`'s own `"⚠"` glyph
(the visual warning marker for an active `ConflictFlag`/`LateArrivalFlag`)
carries through into the simulated tree as literal text
(`"⚠ ConflictFlag"`) — this proves the content reaches the right place in
the tree, but whether a REAL screen reader actually pronounces a bare
Unicode symbol character that way (documented as genuinely inconsistent
across real assistive technology) is something only an actual NVDA/JAWS/
VoiceOver session could confirm. `TODO.md`'s own item updated to
describe this narrowing honestly — still open, still needs a real
session to fully close, now with a much smaller, precisely-named
remaining surface (glyph pronunciation and other real-AT-specific
behavior) rather than the whole component's navigability.

Verified: the new spec file's 5 tests pass; the full `reference-app`
suite (41 tests, up from 36) passes; `npm run build` produces an
unchanged bundle size (`@guidepup/virtual-screen-reader` is a
devDependency, confirmed not bundled).
