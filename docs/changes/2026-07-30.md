# Change log — 2026-07-30

Detailed narrative of one very long session's work, moved out of
`CLAUDE.md` (which now stays a standing-conventions index, not a
changelog) so it doesn't reload into context every session. This is the
"why" behind a lot of what's in the design today — read it if you want
the reasoning, not just the current state; read the ADRs/comparisons/
domain docs themselves if you just want current state.

## Integration status (`docs/design-docs/`, now removed, → primary design)

**Every ADR the design-docs merge implied now exists and is Accepted —
`ADR-021` through `ADR-039`.** Nothing from that merge remains only a
plan; what remained afterward was propagating those decisions into the
surrounding docs that still described the pre-integration shape. Big,
foundational, locked-in decisions, for quick orientation:

- **Full entity-centric rebuild** — `EntityId`, an always-on Entity Store,
  `ExpectedVersion` (`ADR-021`), refined by `Optional<T>` property-level
  patches (`ADR-022`), a persist-everything ingestion posture (`ADR-023`,
  superseding parts of `ADR-011`/`013`/`020`), and optimistic concurrency
  + logical-order fold (`ADR-024`, `ADR-029` — see
  `docs/patterns/interactions/fold-ordering-and-conflict.md` for how the
  two compose).
- **Multi-tenant framework** — `appId` is a real schema-registry scoping
  key (`ADR-030`); the `Orders` walkthrough is a sample application, not
  part of the core engine. (Later revised by `ADR-075` — see below.)
- **Schema evolution went further than design-docs asked for** —
  upcasting is materialized to the log, not just computed live
  (`ADR-018`, `ADR-027`), downcasting exists for legacy consumers
  (`ADR-028`), and compatibility/deployment discipline is explicit
  (`ADR-038`).
- **Two new data planes, deliberately separate from the event log** —
  streaming channels for telemetry/audio/video (`ADR-031`, with
  standard-protocol playback/deep-linking/redaction) and content-addressed
  binary attachments, browsable via GraphQL and plain HTTP — WebDAV
  mounting was considered and explicitly declined (`ADR-032`).
- **Distribution is real** — gossip-topology replication with a minimum
  2-replica, regional-fault-tolerant requirement (`ADR-033`,
  `docs/comparisons/peer-sync-topology.md`) and entity-type-based sharding
  (`ADR-034`, `docs/comparisons/sharding-strategy.md`).
- **Non-authoritative capture** — `AuthorityStatus` as its own trust axis
  (`ADR-035`, `docs/comparisons/authority-rejection-behavior.md`), DID/UCAN
  self-attestation via OAuth Token Exchange (`ADR-036`, un-rejecting what
  `references.md` had marked reference-only).
- **GraphQL replaces OData entirely** (`ADR-037`) — GraphQL queries travel
  over HTTP `QUERY`, never `GET`, specifically to keep PII/PHI-bearing
  filter arguments out of URLs/logs/proxy caches. Supersedes
  `ADR-003`/`04-odata-filter-pushdown.md`'s OData surface and moves
  `ADR-018`'s upcast mechanism off OData `compute()` onto CEL/JSONata.
- **MVVM client + entity views** (`ADR-039`) — sequenced last on purpose,
  composes primitives every earlier ADR already built. Extended with a
  concrete Vue 3 mapping (`docs/patterns/mvvm-client-architecture.md`),
  an installable/offline PWA story (`docs/patterns/pwa-offline-
  outbox.md`), multi-instance support, and an MVVM→MVP→MVC→code-behind
  fallback priority (`docs/comparisons/ui-architecture-patterns.md`).
- **Ticket exchange for header-incapable clients** (`ADR-040`) — closes
  the gap streaming playback and attachment retrieval reopened, via a
  short-lived opaque ticket (RFC 8693 issuance, RFC 7662-shaped
  resolution) plus a client-side HMAC signature.
- **Explicit composition over convention-magic** (`ADR-041`) — Pure DI,
  no AutoMapper, no third-party structured logging, `System.Text.Json`.
- **Gated authoritative publish** (`ADR-042`, revises `ADR-035`) — the
  Entity Store only folds an event once `AuthorityStatus` reaches
  `accepted`; a `LiveEntityStoreRow` folds everything immediately,
  wrapped `isAuthoritative: false`. `AuthorityStatus`'s default flipped
  from `unattested` to `accepted` for ordinary authenticated publishes.
- **Delegated access grants + application-defined permissions**
  (`ADR-043`, `ADR-044`) — UCAN delegation for "secondary opinion"-style
  temporary, capped, entity-scoped access; a per-`AppId` `AppTrustRoot`
  registry for the root-of-trust question UCAN itself leaves out-of-band.
- **Read access audit log** (`ADR-045`) — every read writes an
  `AccessLogEntry`, hash-chained independently from the write side.
- **RBAC + row-level access + federated claims augmentation**
  (`ADR-046`, `ADR-047`, plus a generalization inside `ADR-043`) — base-
  tier ANSI/INCITS 359 RBAC, additive-only permissions, `ADR-043`'s
  entity-scope claim generalized into a standing RLS-shaped primitive,
  `ADR-047` augmenting (never replacing) an external IdP's token.
- **SPIFFE/SPIRE for internal service/peer identity** (`ADR-048`) —
  reverses a prior rejection once the design's own growth created the
  multi-workload-mesh scenario that rejection named as the reason to
  revisit.
- **Entity-level permission/masking metadata via OpenAPI/AsyncAPI
  extensions, reused for log redaction** (`ADR-050`) — generalizes
  `ADR-008`'s one-claim-per-direction limit to a list (`RequiredClaims`).
- **Four more open questions resolved** (`ADR-051`–`053`): static
  `SeedPeers`-only peer discovery; streaming-channel redaction
  (zero-fill/tone/blank-frame default, `PartialReveal` shared with
  `ADR-009`); pluggable upcast engine (CEL default); `RequiredClaims`
  same-direction OR default. `ADR-009` also gained a third masking
  strategy, keyed HMAC `"Hash"`.
- **API Gateway (YARP)** (`ADR-049`) — also reverses a prior rejection,
  same trigger as SPIFFE/SPIRE.

Also landed independently: `ADR-025` (Scalar/AsyncAPI React docs UI),
`ADR-026` (Aspire+OTel dev, Compose prod), and two comparison/pattern
docs on the API query layer (`docs/comparisons/api-query-layer.md`,
`docs/patterns/graphql-query-language.md`/`odata-query-protocol.md`).

**Second wave** (`ADR-054`–`060`) — client SDK generation (Kiota/
Strawberry Shake/GraphQL Code Generator), testing strategy (MSTest+Moq,
Vitest+Vue Test Utils, Playwright), data lifecycle classification,
GDPR/CCPA erasure via crypto-shredding (reverses `ADR-009`'s original
no-deletion stance), per-tenant rate limiting (ASP.NET Core
`RateLimiting`), and extensibility (composition-root-only local
extensions, `ADR-060`'s webhook mechanism reusing the same durable
outbox primitive as `ADR-033`/`039`).

**Third wave** (`ADR-061`–`070`) — data residency (`AllowedRegions`),
package distribution (NuGet/npm, SemVer 2.0.0), secrets management
(an `ADR-041` addendum), staged distributed-correctness testing
(FsCheck+Simmy now, Toxiproxy/Jepsen as named escalations), the
proving-ground domain decision itself (clinical trials + device
telemetry, paired with digital identity/KYC), `ActorId` on every
`StoredEvent`, `IErasureKeyStore` corrected to keyed/multi-backend,
local active-scope caching (`ADR-065`), soft/reveal-on-demand display
masking (an `ADR-009` amendment), digital sign-off via RFC 9470 step-up
auth (`ADR-066`), control-plane actions as reserved events (`ADR-067`),
lineage export + bitemporal playback + a self-contained offline player
(`ADR-068`), pluggable outbox flush triggers (`ADR-069`), and device
input integration (`ADR-070`, WebUSB/WebHID/WebSerial/WebBluetooth +
native-bridge fallback).

**Fourth wave** (`ADR-071`–`074`) — the PCI-DSS Sensitive Authentication
Data registration boundary; bulk ingestion + external interchange-
format adapters (`IInterchangeFormatAdapter`, HL7v2/FHIR inbound,
ICH E2B(R3)/GS1-EPCIS outbound); accessibility as its own standing
requirement (`ADR-073`, deliberately corrected out of `ADR-039` after
direct feedback caught the category error); SBOM generation +
IEC 62304 SOUP list (`ADR-074`).

Alongside these: the proving-ground-domain comparison was extended
twice more (all 15 candidate domains, then a full 72-ADR × 15-domain
coverage matrix), `docs/domains/` was built (2 chosen domains written
directly, 13 considered domains generated by 4 parallel agents grounded
in the coverage matrix), and a traceability/auditability review found
and resolved `ActorId`'s gap plus two forks (signer-erasure exemption,
bundle-format versioning).

## Naming, glossaries, and the multi-tenancy decision

- **Company/product naming** — `docs/naming.md`: OoBDev, **Duplex**
  (engine), **Vitals** (clinical trials), **Meridian** (KYC).
- **A central glossary plus one per domain, with verified synonyms** —
  `docs/glossary.md` (~55 terms) and a `## Glossary` section on all 15
  domain docs (~150 terms), then a synonym-retrofit pass on both (~50
  verified synonyms added), with several deliberately **not** treated as
  synonyms after verification: KYC vs. CDD, Clearinghouse vs. CCP,
  Market Maker vs. Liquidity Provider, De-identification vs.
  Anonymization, Index Case vs. "Patient Zero," Legal Hold vs.
  Litigation Hold.
- **Multi-tenancy: pool model → silo model** — `docs/comparisons/
  multi-tenant-isolation-model.md` + `ADR-075`. Direction received:
  dedicated infrastructure per tenant, not shared ("servers are cheaper
  than lawsuits"). Verified real terminology (AWS's "Silo Isolation,"
  Azure's "Automated single-tenant deployments") before deciding.
  `ADR-030` revised in place for the shared-deployment framing; `AppId`
  itself unaffected. Cross-tenant exchange reuses `ADR-060`/`072`
  (a sibling tenant is "just another external system to federate
  with"), not a new protocol — with one honest, named residual:
  tenant-to-tenant mapping has no external spec to anchor to the way
  HL7v2/FHIR do (`docs/10-open-questions.md` row 22).
- **Smaller mid-conversation resolutions**: `ADR-034` sharding now
  explicitly optional under the silo model; `ADR-032` gained a keyed
  multi-backend `IAttachmentContentStore` (`ADR-057`'s shape, applied to
  content tiering) plus content-defined chunking (verified against
  restic/Borg/casync/rsync/BitTorrent/IPFS) for real sub-file dedup and
  partial sync; `ADR-043` gained a true-offline break-glass composition
  (`ADR-036`'s DID key + this ADR's UCAN delegation); the authority-
  rejection-behavior comparison was sharpened into "annotate-only plus a
  targeted single-entity rebuild," resolving a real retraction gap an
  independent cross-reference had named without inheriting the
  Compensating-patch option's ambiguous-revert-semantics problem.
  `docs/10-open-questions.md` rows 11/17/18 narrowed/resolved; rows 20
  (`ThreadId`) and 21 (frontier tokens/read-your-writes) added.

## A three-lens design review of this session's own rapid changes

Direct request: "do a design review to see what's missed." Three
parallel review agents, each a different lens:
1. **Propagation audit** of everything above — found `01-c4-
   architecture.md`, `06-solution-structure.md`, `08-build-plan.md`
   Phase 12, `docs/extensibility-points.md`, and `references.md` all
   hadn't caught up to `ADR-075`/`032`'s new fields — fixed.
2. **Fresh-eyes contradiction hunt** across all 75 ADRs (not summaries —
   full text) — found the session's most valuable bugs: `ADR-032`
   decided against WebDAV mounting ("skipped, not built") but kept
   describing it as if shipped, which had leaked into `ADR-040`,
   `ADR-049`, `ADR-045`, and half a dozen core docs — fixed everywhere
   (confirmed both `ADR-040`/`049` remain fully coherent without it).
   `ADR-046`/`047`/`067` disagreed about who owns `Role`/`UserPermission`
   (resolved in `ADR-067`'s favor, the later decision). `ADR-018` was
   never actually revised off OData despite `ADR-037` saying it needed
   to be, and `CLAUDE.md` incorrectly claiming it had been — rewritten
   in place onto CEL. `ADR-068`'s offline player claimed independent
   hash re-verification "from the math alone" even for masked/erased
   content — mathematically impossible for exactly the redacted fields;
   corrected to an honest, qualified limitation. `ADR-020` still showed
   pre-`ADR-023` `400`/`201` responses; Entity Store `Version` was
   defined two contradictory ways across `ADR-021`/`029`; several wrong
   ADR-number citations and two stale "still open" claims `ADR-045` had
   already resolved.
3. **Buildability check** on this session's newest mechanisms — found
   `ADR-032`'s "partial sync" claim needed independently-addressable
   chunks (fixed: `ChunkRef` now carries its own
   `ContentProviderKey`/`Ref`, not just an offset into one blob);
   `ADR-021` needed a real, new `QUERY /entities/{entityId}/events`
   path for the targeted-rebuild refinement to work at all (added);
   `ADR-043`'s break-glass composition needed `ADR-017`'s already-
   specified device-keypair provisioning cross-referenced, since
   `ADR-036` alone never said how a device gets/protects its DID key
   (fixed); `ADR-075`'s tenant-to-tenant federation claim got the
   honest residual named above rather than glossed over.
