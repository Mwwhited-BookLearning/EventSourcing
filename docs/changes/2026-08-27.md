## Research that shaped the design

Two verified findings changed the shape of the design before any doc was
written:

- `EnvelopeAesGcm` (`ADR-057`) already uses a deterministic nonce
  (`HMACSHA256(key, plaintext)[..12]`, required for `ADR-011`
  idempotency) — equal plaintexts already produce identical ciphertext
  *within one entity's key*. The actually-useful case (cross-entity
  search) needs a token comparable across independently-destroyable
  entity keys, which a purely per-entity key structurally cannot give.
- Property-preserving encryption's leakage-abuse break
  ([Naveed/Kamara/Wright, CCS 2015](https://www.microsoft.com/en-us/research/publication/inference-attacks-property-preserving-encrypted-databases/))
  recovers **exact plaintext**, not a fuzzy guess, for low-cardinality
  fields (birthdate, zip code, a diagnosis code) — verified directly
  against the paper this session after the user asked specifically
  whether a name could be recovered the same way. Answer, confirmed
  against the source: no, not to the same degree — the attack's power
  is concentrated in a small, guessable value domain; a high-cardinality
  field like a name is meaningfully more resistant. This directly shaped
  `ADR-096`'s guardrail into a cardinality-aware rule instead of a
  blanket classification rule.

## Decisions made, by direct user choice among researched options

1. **Build real, working examples of both** the safe bucketed-index
   approach and real Order-Revealing Encryption, each documented with
   its own pros/cons — not just adopt one and decline the other.
2. **Support both index-key scopes** (`Shared`, for real cross-entity
   search, with erasure deleting that entity's own derived index rows;
   `PerEntity`, for true crypto-shredding of the index token itself, at
   the cost of only ever answering single-known-entity lookups) as a
   per-field configurable choice, confirmed to never touch `ADR-019`'s
   hash chain or `ADR-033`'s Merkle-tree replication-sync (both operate
   only over `StoredEvent`/`Payload`).
3. **Queries should run inside the database as much as possible** —
   this is *why* the ORE option was built as a real alternative (the
   database compares ciphertext directly, zero decryption needed to
   filter) rather than only documented and declined, and why `ADR-098`
   designs an in-database native predicate evaluator seam
   (SQLCLR/PostgreSQL/SQLite) even though only its default app-tier
   implementation ships this pass.

## Implementation pass (later the same day, direct request: "start building all of this work")

Built and tested items 54 and most of 55 against the design above, on the
same `dev/cryptoshredding` branch.

**Real findings during build, not assumed from the design docs**:
- **Found and fixed a prerequisite bug**: `PayloadEncryptor` (`ADR-057`'s
  own encryption) was never registered in any Host's DI — every real
  `PublishService` resolved it as `null`, so classified-field encryption
  was inert in production before this fix, exercised only by test code.
- `IErasureKeyStore` never exposes raw DEK bytes, so `PerEntity` key
  derivation is `SHA-256(EncryptAsync(keyReference, a fixed info
  string))`, not a literal HKDF — deterministic, entity-key-dependent,
  and permanently uncomputable once the DEK is destroyed.
- `ISearchIndexKeyStore`'s real shape is `ComputeHmacAsync(keyReference,
  data)`, not an envelope encrypt/decrypt pair — a Shared-scope index key
  computes a MAC, it never encrypts data at rest.
- `EncryptedFieldIndexEntry.Token` is a base64 `string`, not `byte[]` —
  corrected in `docs/data/schema-registry.md` in the same pass.
- `GraphQlFilterPredicateBuilder.Build` became `async` (resolving matches
  needs a database query); a bucketed range query now requires both a
  lower and upper bound in one clause (an open-ended range would
  enumerate an unbounded number of buckets).
- The ORE query path's app-tier default compares ciphertext in
  application memory across a field's own indexed rows, not via a native
  SQL operator — a real, named gap `ADR-098`/item 56 exists to close.
