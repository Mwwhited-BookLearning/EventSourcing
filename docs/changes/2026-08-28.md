# 2026-08-28

## Fixed ADR-096's registration guardrail: cardinality check now covers `Equality`, not just `Range`

Found while reviewing Vitals/Meridian (the two proving-ground domains)
for real `x-masking-searchable` candidates the previous session — a
genuine gap in already-shipped, "Done"-marked code: `MaskingSchemaValidator.
ValidateSearchableConfig` only required a `cardinality` hint for `Range`-
kind fields. But [Naveed/Kamara/Wright, CCS 2015](https://www.microsoft.com/en-us/research/publication/inference-attacks-property-preserving-encrypted-databases/)
— the same paper the guardrail already cites — names **deterministic
encryption** as frequency-analysis-vulnerable, and a blind `Equality`
index is deterministic encryption by definition (same plaintext, same
ciphertext, always). A `Low`-cardinality classified field (Meridian's
`MatchedListEntryId` — a bounded, enumerable sanctions-list domain) could
register `Equality` with zero guardrail coverage before this fix.

- `src/EventStore.SchemaRegistry/MaskingSchemaValidator.cs`: the
  cardinality/`acknowledgeLeakageRisk` check now runs for `indexKind is
  "Equality" or "Range"`, not `"Range"` alone; `bucketGranularities` stays
  required for `Range` only.
- `docs/adrs/adr-096-searchable-blind-index-bucketed-range.md` and
  `docs/data/schema-registry.md` corrected in the same pass (additive —
  states the original Range-only scope and why it was widened, not a
  silent rewrite).
- New regression tests in `SearchableEncryptionSqliteTests.cs`: a
  `Low`-cardinality classified `Equality` field is rejected without
  `acknowledgeLeakageRisk`, succeeds with it, and a field with no
  `cardinality` declared at all is rejected regardless of classification
  (matching `Range`'s existing unconditional-requirement behavior). The
  pre-existing equality-query test's own schema needed `cardinality:
  "High"` added (`Email`, genuinely high-cardinality) to keep passing
  under the now-stricter rule.
- Full suite verified: unit (17/17), Sqlite integration excluding the
  known pre-existing auth-flakiness classes (142/142) — no regressions.
